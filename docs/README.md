# OctoAcme Project Management

This folder collects OctoAcme's project management process documents and provides a brief overview so team members can quickly find guidance and reference materials.

Overview
OctoAcme runs projects through a lightweight, repeatable lifecycle: Initiation, Planning, Execution, Release, and Retrospective. Initiation uses a Project One‑pager to validate the problem, define SMART objectives, and identify stakeholders. Planning breaks approved work into a prioritized backlog with acceptance criteria, estimates, a Definition of Done, and a release/milestone map. Execution uses a project board (Backlog → Ready → In Progress → In Review → QA → Done) and small, CI‑tested pull requests to deliver increments of value.

Workflows & Roles
Roles are explicit: Product Managers set outcomes and priorities, Project Managers coordinate schedules, risks, and stakeholder communication, Developers implement and test, and QA validates acceptance criteria. The docs include templates for backlog items, the risk register, and other artifacts to make responsibilities and handoffs clear.

Communication & Quality
Team rhythm includes short daily standups, weekly delivery syncs, sprint/milestone demos, and periodic stakeholder updates. Escalation paths are defined (team → PM → Product Lead → Sponsor), and security incidents follow the security runbook. Quality relies on automated unit/integration tests, CI security scans, and end‑to‑end smoke tests for critical flows; manual QA is used for feature acceptance when needed. Release readiness requires passing CI, documented rollback plans, and pre/post‑deploy verifications.
